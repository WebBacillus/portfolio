# Triage roles on Hermes Kanban

The canonical names stay unchanged. Kanban has no labels: store exactly one `**Status:**` state role and one `**Type:**` category role near the top of each triaged card's body. The body marker is the triage source of truth; the column is the operational dispatch state. All commands below use `hermes kanban --board default` and cards with tenant `portfolio`.

| Canonical state role | Body marker | Operational representation |
| --- | --- | --- |
| `needs-triage` | `**Status:** needs-triage` | `triage`; create with `--triage` |
| `needs-info` | `**Status:** needs-info` | `blocked`; use `block <id> --kind needs_input "<question>"` once the card is in an eligible active column |
| `ready-for-agent` | `**Status:** ready-for-agent` | `ready` (or parent-gated `todo`); assign to an existing agent profile only when ready to dispatch |
| `ready-for-human` | `**Status:** ready-for-human` | `ready`, unassigned; leave unassigned so the dispatcher does not start an agent |
| `wontfix` | `**Status:** wontfix` | Comment with the rationale, then `archive <id>` |

Category roles have no column: write `**Type:** bug` or `**Type:** enhancement` in the body. Preserve the rest of the body when replacing a marker. Triage comments must begin with `> *This was generated by AI during triage.*`.

Read `show <id> --json` before any transition, including its tenant, column, body, and assignee. The CLI has no generic status setter. A `triage` card can be specified with `specify <id>` (which can rewrite its title/body and move it to `todo`), or moved manually in the Kanban dashboard after its brief is ready; do **not** run `specify` over a carefully written brief merely to change columns. Verify the actual column with `show` before assigning or blocking it. `promote <id> "<reason>"` only moves from `todo` when all blocking parents are done; `link`/`unlink` do not change the column. For `needs-info` after a reporter replies, `unblock <id> --reason "<reason>"` restores it to `ready` (or parent-gated `todo`), not `triage`; update the body role and explicitly re-evaluate it before assigning. `ready-for-human` relies on unassigned cards not being dispatched: if `kanban.default_assignee` becomes configured, verify that behavior before using this representation. Read the exact card back with `show <id> --json` after every change.
