# Streamlit inside the Next.js portfolio chat

**Recommendation:** For an in-page, portfolio-branded public chat about projects and job fit, use a native Next.js **Client Component** for conversation state and input, calling the LangGraph/FastAPI service (preferably through a Next.js `app/api/.../route.ts` handler if server-side secrets, rate limits, or a same-origin browser endpoint are needed). This is an architectural recommendation, not a claim that Streamlit cannot be embedded. Next.js explicitly supports interactive Client Components and POST Route Handlers; keep model credentials on the server. [Next.js Client Components](https://nextjs.org/docs/app/getting-started/server-and-client-components) · [Next.js Route Handlers](https://nextjs.org/docs/app/getting-started/route-handlers)

| Option | How it works | Fit here |
| --- | --- | --- |
| Streamlit embed | Host a **separate Python Streamlit app**; render `<iframe src="https://YOUR-APP.streamlit.app/?embed=true" title="Portfolio chat" style={{ width: '100%', height: 600 }} />` within a Next.js page or panel. Community Cloud documents iframe embeds for **public** apps; `embed=true` removes toolbar, top/bottom padding, footer, and top stripe; theme and other embed options are available. It explicitly does **not** officially support embedding private apps. [Streamlit embedding](https://docs.streamlit.io/deploy/streamlit-community-cloud/share-your-app/embed-your-app) | Fast standalone demo, but visually and operationally a second app. |
| Native Next.js chat | Implement the chat UI as a `'use client'` React component, issue requests to a same-origin Next.js route handler forwarding to FastAPI/LangGraph (or directly to an appropriately secured/CORS-configured API), and render replies in the portfolio's own DOM. [Client Components](https://nextjs.org/docs/app/getting-started/server-and-client-components) · [Route Handlers](https://nextjs.org/docs/app/getting-started/route-handlers) | Better integration with existing navigation, styles, accessibility and application state; no embedded Streamlit server required. |

**Not a React injection API:** Streamlit custom components extend *a Streamlit app*, not a Next.js component tree. Current Streamlit components v2 run within the Streamlit page and communicate with Streamlit's Python runtime; legacy v1 components run in Streamlit-managed iframes. Neither turns a Python Streamlit UI into an importable React chat widget for Next.js. Likewise, `st.components.v1.iframe` embeds web content **into Streamlit**, the opposite direction. [Streamlit component overview](https://docs.streamlit.io/develop/concepts/custom-components/overview) · [Streamlit v1 iframe API](https://docs.streamlit.io/develop/api-reference/custom-components/st.components.v1.iframe)

## Iframe constraints to budget for

- **Styling and layout:** Parent CSS can size/decorate the `<iframe>` element but cannot directly style a cross-origin app's internal DOM. Streamlit embed parameters/theme can adjust its own chrome, not make its UI inherit the portfolio's CSS. Independently manage frame height/mobile sizing, internal scroll, focus and loading. [Streamlit embedding](https://docs.streamlit.io/deploy/streamlit-community-cloud/share-your-app/embed-your-app) · [MDN iframe/same-origin policy](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)
- **Routing and state:** The frame navigates within its own document and URL; Next.js routing/layout and chat state do not become shared automatically. The Streamlit server uses a persistent WebSocket, with a separate session per browser tab/window; deployment must keep the app reachable and support WebSockets (and possibly sticky sessions with replicas). [Streamlit architecture](https://docs.streamlit.io/develop/concepts/architecture/architecture) · [Next.js Route Handlers](https://nextjs.org/docs/app/getting-started/route-handlers)
- **Hosting and frame policy:** Community Cloud public-app iframe embedding is documented, but still requires a separate deployment. For another host, verify it allows framing by the portfolio origin; the embedded app's `Content-Security-Policy: frame-ancestors` controls who may frame it, while the parent's `frame-src` controls what it may load. [Streamlit embedding](https://docs.streamlit.io/deploy/streamlit-community-cloud/share-your-app/embed-your-app) · [MDN frame-ancestors](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors)
- **Auth/cookies:** Do not rely on the portfolio's auth or cookies automatically carrying into a differently hosted Streamlit origin. Community Cloud does not officially support embedding private apps. Cross-site iframe cookies face `SameSite`/`Secure` requirements and browser third-party-cookie policies; Streamlit documents `server.xsrfCookieSameSite = "none"` for cross-origin embeds needing XSRF cookies (e.g. file upload), requires HTTPS, and warns of the CSRF tradeoff. Preserve XSRF/CORS protections rather than disabling them as a workaround. [Streamlit embedding](https://docs.streamlit.io/deploy/streamlit-community-cloud/share-your-app/embed-your-app) · [Streamlit config](https://docs.streamlit.io/develop/api-reference/configuration/config.toml) · [MDN cookies](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Cookies)
- **Cross-origin messages:** Parent code cannot read/control the frame DOM or conversation state directly. Any explicit cross-frame integration needs code on **both** sides using `window.postMessage`, with a fixed `targetOrigin` and validated incoming `event.origin`; `embed=true` alone is not a chat-state bridge. [MDN iframe](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe) · [MDN postMessage](https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage)

This is documentation research only; no deployed embedding or cross-browser cookie behavior was tested.
